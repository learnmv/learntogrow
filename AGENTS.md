# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project Overview

LearnToGrow is an AI-powered educational question generation platform built around California Common Core curriculum standards. It consists of a FastAPI backend (Python) and a React frontend (TypeScript + Vite).

## Architecture

### Backend (FastAPI)

Layer-based architecture in `backend/app/`:
- **Routers** (`routers/`) - HTTP request handling, route definitions
- **Services** (`services/`) - Business logic, Ollama LLM integration for question generation
- **Models** (`models/`) - SQLAlchemy ORM models for curriculum hierarchy (subjects → grades → domains → clusters → standards) and user system
- **Schemas** (`schemas/`) - Pydantic request/response validation

Key endpoints under `/api/v1`: `/subjects`, `/grades`, `/domains`, `/clusters`, `/standards`, `/questions/generate`, `/auth`, `/admin`, `/parent`

The backend connects to PostgreSQL for curriculum data and Ollama (local LLM) for question generation. Configuration via `backend/.env` or environment variables.

### Frontend (React + TypeScript + Vite)

Standard Vite React project in `frontend/`:
- **Entry**: `src/main.tsx` → `src/App.tsx`
- **Components** (`components/`) - React components including `Quiz.tsx`, `ui/` subcomponents, and `admin/` for admin dashboard
- **Services** (`services/`) - API client utilities (`api.ts` fetch wrapper, `standards.ts` curriculum API, `questions.ts` generation API, `auth.ts` authentication)
- **Types** (`types/`) - TypeScript interfaces matching backend schemas

Styling uses Tailwind CSS 4 with custom color palette (sage, coral, sand) defined in `src/index.css`.

### User System

Recently added authentication system with three roles:
- **Student** - Self-register, take quizzes, view progress
- **Parent** - Register with student link request, view linked children's progress (requires admin approval)
- **Admin** - Manage users, generate questions, approve parent-student links

Passwords hashed with PBKDF2, JWT tokens for authentication.

### Student Question Tracking

Students who are logged in have their answers tracked in the `answered_questions` table. This enables:
- Progress tracking (questions answered, accuracy, standards attempted)
- Question exclusion (students don't see questions they've already answered)
- History viewing in the student dashboard

The frontend sends auth headers when fetching questions (`getAuthHeaders()`), and the backend excludes answered questions from the response.

### GeoGebra Integration

Interactive math diagrams using GeoGebra applets:
- Applet types: `graphing`, `geometry`, `3d`, `classic`
- Commands generated by LLM and stored in `questions.geogebra_commands` (JSONB)
- Frontend components in `components/graphing/`, `components/geometry/`, etc.

## CI/CD

GitHub Actions workflows use a self-hosted runner:
- **Dev** (`.github/workflows/dev.yml`): Builds images on push to `dev` branch with versioned tags (`dev-{TIMESTAMP}-{SHA}`)
- **Prod** (`.github/workflows/prod.yml`): Builds images on push to `main` with versioned tags (`prod-{TIMESTAMP}-{SHA}`), creates GitHub release

Both workflows use versioned image tags to trigger Kubernetes rollouts. The `:dev` and `:stable` tags are kept as aliases for easy rollback.

Kubernetes manifests in `k8s/`:
- Deployments use `imagePullPolicy: Always`
- Requires `k8s/secrets.yaml` (gitignored) for database credentials
- Ingress configured for `learntogrow.local`
- Dev namespace: `learntogrow-dev`, Prod: `learntogrow-prod`

- Database connection: `backend/app/database.py`

## Code Patterns

### Adding a Backend Endpoint

1. Add service method in `app/services/<service>.py`
2. Add route in `app/routers/<entity>.py`
3. Update `app/schemas/<entity>.py` if response model changes
4. Register router in `app/main.py` with `app.include_router()`

### Frontend API Calls

Use the typed service functions in `frontend/src/services/`:
```typescript
import { fetchSubjects } from './services/standards'
const subjects = await fetchSubjects()
```

The `fetchApi` wrapper in `api.ts` handles JSON parsing and error throwing for non-OK responses.

### Authentication

Backend uses JWT tokens. Include in requests:
```typescript
import { getAuthHeaders } from './services/auth'
fetch('/api/v1/admin/users', { headers: getAuthHeaders() })
```

### Question Generation Flow

1. Admin selects subject/grade/standards in admin dashboard
2. `AdminService.generate_questions_for_standards()` calls `QuestionService.generate_question()` for each standard
3. QuestionService builds prompt from template in `prompts/`, calls Ollama API
4. Response validated, cleaned, GeoGebra commands added if diagram required
5. Question saved to database, linked to standard

## External Dependencies

- **PostgreSQL**: External database at configurable host (default: `10.0.0.131:30432`)
- **Ollama**: Expected at `http://localhost:11434` (or `http://host.docker.internal:11434` in containers)
- **Kubernetes**: Self-hosted cluster with nginx-ingress controller
- **GeoGebra**: CDN-loaded from `https://www.geogebra.org/apps/deployggb.js`

- `dev` deploys to `learntogrow-dev`.
- `main` deploys to `learntogrow-prod`.

- Use `scripts/promote-dev-to-main.ps1` for the standard promotion flow when the working tree is clean.

### Ollama Cloud

The app is now intended to use direct Ollama Cloud API:

```text
OLLAMA_URL=https://ollama.com
OLLAMA_MODEL=gemma4:31b
OLLAMA_GENERATION_WORKERS=3
OLLAMA_ENABLE_STRUCTURED_OUTPUTS=false
```

Use `OLLAMA_API_KEY` from Kubernetes secrets. Never print secret values. Verify only whether a key exists.

Helpful scripts:

```powershell
.\scripts\patch-ollama-secret.ps1 -Environment dev
.\scripts\patch-ollama-secret.ps1 -Environment prod
.\scripts\verify-ollama-cloud.ps1 -Environment dev
.\scripts\verify-ollama-cloud.ps1 -Environment prod
```

### Migrations

Prod and dev database migrations may need to be applied manually through kubectl. Use:

```powershell
.\scripts\apply-migration.ps1 -Database dev -Migration backend\app\migrations\<file>.sql
.\scripts\apply-migration.ps1 -Database prod -Migration backend\app\migrations\<file>.sql
```

Known important migration for the admin question generation quality pipeline:

```text
backend/app/migrations/016_add_generation_quality_pipeline.sql
```

If prod logs show `column "quality_mode" of relation "generation_jobs" does not exist`, apply migration `016` to `learntogrow_prod`.
